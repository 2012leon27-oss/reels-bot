# Telegram Business AI Assistant

Личный ассистент для Telegram Business. Он получает сообщения из выбранных
личных чатов владельца, хранит отдельную историю по каждому собеседнику,
готовит ответ в стиле владельца и отвечает от его имени только в безопасных
сценариях. Важные, сомнительные и неподдерживаемые сообщения отправляются
владельцу на подтверждение.

## Что технически возможно

- Telegram присылает боту `business_message` с идентификаторами подключения,
  чата, сообщения и собеседника.
- Ответ отправляется от имени Business-аккаунта с `business_connection_id`.
- Новые входящие и исходящие сообщения сохраняются в PostgreSQL отдельно для
  каждого чата.
- Владелец получает обычное Telegram-уведомление от бота с сообщением,
  причиной остановки, черновиком и кнопками.
- Владелец может отправить черновик, пропустить сообщение либо ответить своим
  текстом на уведомление.

Telegram не отдаёт боту всю старую переписку задним числом. История начинает
накапливаться после подключения. Старые важные факты нужно внести в заметки или
контекстные файлы.

## Безопасное поведение

Система работает по принципу fail closed:

1. Автоответы выключены по умолчанию.
2. Шаблонные контекстные файлы блокируют автоответы, пока не заполнены.
3. Новый контакт не получает автоответы до команды `/allow <chat_id>`.
4. Деньги, встречи, сроки, обещания, конфликты, здоровье, документы, адреса и
   чувствительные данные всегда передаются владельцу.
5. Низкая уверенность, ошибка LLM, отсутствие права Telegram или ошибка
   доставки приводят к эскалации, а не к случайному ответу.
6. Повторные Telegram-апдейты отсекаются уникальным ключом сообщения.
7. Обработка каждого чата сериализована, чтобы параллельные сообщения не
   смешивали контекст.

Содержимое переписки передаётся выбранному LLM-провайдеру. Перед эксплуатацией
нужно оценить требования к приватности и выбрать подходящего провайдера.

## Подготовка

Требуются:

- Python 3.11+;
- PostgreSQL;
- Telegram Premium с доступом к Telegram Business;
- новый токен бота от [@BotFather](https://t.me/BotFather);
- ключ OpenAI-совместимого LLM API (по умолчанию Groq).

Скопируйте `env.example` в `.env` и заполните значения. Никогда не коммитьте
`.env`.

Старые Telegram- и Groq-токены из предыдущей версии были опубликованы в Git.
Их необходимо отозвать и создать заново: простого удаления из текущего файла
недостаточно, потому что секреты остаются в истории репозитория.

## Установка и локальный запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 bot.py
```

При запуске таблицы PostgreSQL создаются автоматически. Старые таблицы проекта
не удаляются.

## Подключение к Telegram Business

1. Откройте диалог с новым ботом и нажмите **Start**. Без этого бот не сможет
   гарантированно присылать уведомления владельцу.
2. В BotFather включите для бота Business Mode, если он ещё не включён.
3. В Telegram откройте **Настройки → Telegram Business → Чат-боты**.
4. Подключите бота, выберите нужные личные чаты и дайте право отвечать.
5. Проверьте `/status`. При подключении бот также сообщает, есть ли право
   отвечать.

Telegram разрешает Business-боту отвечать только в управляемых личных чатах,
в которых было входящее сообщение в пределах окна, установленного Telegram
(сейчас 24 часа).

## Настройка контекста

Заполните:

- `contexts/owner.md` — факты о владельце;
- `contexts/style.md` — стиль и примеры реальных сообщений;
- `contexts/rules.md` — разрешённые темы и границы;
- `contexts/contacts/<chat_id>.md` — необязательный подробный контекст человека.

Маркер `[TODO:` намеренно блокирует автоответы. Удалите все такие маркеры после
заполнения. Короткую персональную заметку можно добавить командой:

```text
/note <chat_id> <кто это, отношения, текущий контекст>
```

## Включение автоответов

1. Сначала тестируйте с `AUTO_REPLY_ENABLED=false`: все сообщения будут только
   приходить на проверку.
2. Заполните контекст и проверьте уведомления/ручную отправку.
3. Установите `AUTO_REPLY_ENABLED=true`, перезапустите сервис.
4. Разрешите один тестовый контакт: `/allow <chat_id>`.
5. Выполните `/resume`.
6. Только после проверки постепенно разрешайте остальные контакты.

Команды владельца:

| Команда | Назначение |
| --- | --- |
| `/status` | состояние, статистика, наличие контекста |
| `/pause` | немедленно остановить все автоответы |
| `/resume` | включить автоответы при соблюдении защитных условий |
| `/pending` | повторно показать до 10 ожидающих решений |
| `/allow <chat_id>` | разрешить автоответы контакту |
| `/block <chat_id>` | запретить автоответы контакту |
| `/note <chat_id> <текст>` | сохранить персональный контекст |

## Развёртывание на Render

- Build command: `pip install -r requirements.txt`
- Start command: `python3 bot.py`
- Добавьте PostgreSQL и все переменные из `env.example`.
- Health check path: `/health`.
- Должен работать ровно один экземпляр polling-процесса, иначе возможны
  конфликты получения Telegram-апдейтов.

Для более строгой production-инфраструктуры polling можно заменить webhook,
но текущая реализация корректно работает на одном постоянно запущенном
экземпляре.

## Проверка

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q .
```

Проверки без реальных Telegram/PostgreSQL/LLM-ключей покрывают конфигурацию,
парсинг решения модели, защитные правила и блокировку незаполненного контекста.
Перед включением автоответов обязателен ручной end-to-end тест через отдельный
Telegram-аккаунт.

## Переменные окружения

| Переменная | Описание |
| --- | --- |
| `BOT_TOKEN` | новый токен Telegram-бота |
| `OWNER_ID` | числовой Telegram ID владельца |
| `DATABASE_URL` | PostgreSQL DSN |
| `LLM_API_KEY` | ключ LLM |
| `LLM_BASE_URL` | OpenAI-совместимый endpoint |
| `LLM_MODEL` | модель провайдера |
| `AUTO_REPLY_ENABLED` | глобальный предохранитель |
| `ESCALATE_UNKNOWN_CONTACTS` | отправлять новые контакты владельцу |
| `CONFIDENCE_THRESHOLD` | минимальная уверенность модели, 0–1 |
| `HISTORY_LIMIT` | число сообщений контекста, 1–100 |
| `LLM_TIMEOUT_SECONDS` | таймаут одного запроса |
| `LLM_MAX_RETRIES` | число попыток LLM, 1–5 |
| `PORT` | порт health-сервера |
